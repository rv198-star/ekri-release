# EKRI v0.9.0 Release Notes

Status: `released-with-claim-ceiling` — independently versioned EKRI product Release. EKRI v0.9.0 was originally jointly frozen with WFF v1.9.2; the later WFF v1.9.2 packaging-only refresh moved only the WFF source tag, while `ekri/v0.9.0` remains on its original validated EKRI source commit.

## Release Mission

EKRI v0.9.0 is the first formally governed independent EKRI product baseline while EKRI remains co-located with WFF in the same repository.

It establishes independent:

- semantic versioning;
- `EKRI/CHANGELOG.md`;
- `ekri/vX.Y.Z` tag namespace;
- GitHub Release identity;
- Python 3.12 EKRI CI;
- release Gate and claim ceiling;
- M0 semantic/query/complexity baseline for the v1.0 architecture transition.

## Added Since Historical Package Milestone 0.8.0

### Portable Project Knowledge

Tracked `.EKRI/project/**` assets can preserve content-addressed, evidence-linked project knowledge across clean worktrees while all `EKRI/**` and `.EKRI/**` remain excluded from formal target observation.

Verification reopens named Git evidence, verifies artifact/evidence digests and closure, rejects machine-local absolute-path authority, and keeps hydration separate from currentness.

### Repository Asset Identity

EKRI reconstructs stable repository asset identities with:

- stable identity across physical relocation;
- exact Git manifestation identity;
- observed roles;
- single-owner / multi-owner / unresolved ownership evidence;
- capability and dependency references;
- explicit unknown preservation;
- no autonomous retirement authority.

### Repository Ownership Boundary

EKRI reconstructs structural coupling and accepted authority evidence without allowing structural topology to establish semantic ownership.

Structural imports/references remain evidence-bounded and graph misses do not become dependency-absence proof.

### Repository Lifecycle Observation

EKRI records current-tree lifecycle evidence for known assets and compatibility surfaces, including package membership, imports, exact references, LOC, and observation classes.

Observation history does not autonomously create deprecation, retirement, removal, or deletion authority.

### Independent EKRI CI

A dedicated GitHub Actions workflow now runs on EKRI changes with Python 3.12 and covers:

- EKRI source/test/script compilation;
- full EKRI regression suite;
- clean EKRI Phase 0/1/2 bootstrap validation.

## Changed

- EKRI is now governed as an independent product line rather than inheriting WFF version/release identity.
- WFF remains the first host/stress corpus and compatibility evidence source, not the semantic definition of EKRI.
- Product-version, schema-version, component/scanner-version, and host/target-version identities are explicitly separate.
- The v1.0 architecture direction is accepted: a rich but shallow Engineering Knowledge Model with named Query/View contracts and progressive disclosure, normalized internally through `Object / Occurrence / Assertion`.

## Claim Ceiling

It does not claim:

- ontology-native runtime authority;
- full general Engineering Knowledge System implementation;

- absence proof outside declared complete observation boundaries;
- autonomous engineering or governance decision authority;
- production approval/UAT of WFF or another host;
- standalone repository/distribution maturity unless separately proven.

## Independent Release Pack

Starting with this release, EKRI publishes its own downloadable package rather than relying only on repository source/tag access.

The v0.9 package is intentionally a **Git-provenance-preserving source/runtime distribution**:

- package root contains top-level `EKRI/`;
- includes current runtime source, CLI scripts, schemas, WFF-profile specs, the committed audit fixture, and bounded product/operation documentation;
- excludes EKRI tests, WFF change-registration history, `.EKRI/**` runtime state, WFF runtime/install-pack content, and the v1.0 ontology exploration/audit corpus;
- includes `EKRI_RELEASE_PACK_MANIFEST.json` with exact source revision/tree, per-file digests, package claim ceiling, and a separately recorded packager revision;
- includes `SHA256SUMS` beside the zip in the GitHub Release.

For v0.9 Formal Scanner use, extract the package into a scanner-control Git repository, keep the supplied package-root `.gitignore`, and commit the `EKRI/` surface before formal observation. The package does not add a non-Git provenance fallback.
