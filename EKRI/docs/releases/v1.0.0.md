# EKRI v1.0.0 — Engineering Knowledge System Architecture Release

Date: 2026-08-13  
Status: **Release Candidate source record — not yet published/tagged**

## Release Mission

EKRI v1.0.0 is the first deliberately supported general Engineering Knowledge System architecture release.

It moves EKRI from the v0.9 evidence-bounded reconstruction/intelligence baseline to a supported product architecture with:

- a rich but shallow Engineering Knowledge Model;
- internal Object / Occurrence / Assertion semantic normalization;
- named Query/View contracts and L0-L3 progressive disclosure;
- explicit evidence, source Context, epistemic and authority qualification;
- one semantic authority per knowledge slice/context;
- a completed Capability semantic-authority cutover and legacy-writer retirement;
- bounded general Flow/Handoff query without a Flow truth store;
- WFF and unrelated non-WFF conformance.

## Major Changes Since v0.9.0

### Engineering Knowledge Model / semantic substrate

- Added the governed v1.0 Engineering Knowledge Model architecture.
- Added read-only shadow semantic normalization through Object / Occurrence / Assertion for migration/conformance work.
- Preserved semantic identity separately from exact materialization/projection identity.
- Added explicit `conflicting` epistemic posture alongside observed, inferred and unknown.

### Architecture View

- Added `ekri.architecture-view.v1`.
- Proved current Architecture Memory round-trip parity across source Context, identity/structure, responsibility/non-responsibility, intent, assurance, constraints, unknown posture, evidence and claim ceiling.
- Architecture View remains derived; it is not a peer Architecture writer.

### Capability

- Added ontology-authoritative `ekri.capability-semantic-authority.v1`.
- Added named Capability queries:
  - `find_capability(...)` / `find-capability`;
  - `get_realizations(...)` / `get-realizations`;
  - `explain_authority(...)` / `explain-authority`;
  - `get_evidence(...)` / `get-evidence`.
- Preserved false-absence behavior: a miss never proves capability absence.
- Completed the first bounded semantic-authority cutover.
- Retired the old private Capability Catalog semantic writer/evaluator.
- Kept the v0.9 Capability Catalog / Before Generate output as derived WFF compatibility only.
- Rebound Core Boundary and Evolution to the sole Capability Authority rather than rebuilding a legacy Catalog.

### Flow / Handoff

- Added bounded `trace_flow(...)` / `trace-flow` with L0-L3 disclosure.
- Represents FlowDefinition as knowledge, bounded handoffs as Occurrences and route/carriage/authority/reliance/order as qualified relations.
- Does not introduce a peer Flow semantic store.
- Includes WFF and generic CI conformance fixtures.

### Repository identity / ownership / lifecycle firewalls

- Stress-tested 3,250 repository assets, 12,499 raw structural edges and lifecycle/compatibility boundaries through the shared model.
- Preserved stable asset identity across moves.
- Preserved compatibility-surface identity separately from moved implementation identity.
- Preserved unresolved and multi-owner states instead of promoting topology to ownership truth.
- Kept structural observations below semantic authority.
- Retained no-retirement/no-deletion authority ceilings.

### Non-WFF product conformance

- Added the unrelated Mercury CI software-delivery conformance corpus.
- Verified fixture specification and source evidence from exact Git blobs.
- Proved the same Architecture View, Capability Authority/L0-L3 query and Flow query surfaces without WFF P1/P2/P3/P4/PX concepts in the general semantic boundary.
- Preserved contradictory deployment-owner evidence as `conflicting`, with both owner alternatives visible and `existence=unknown`.
- Preserved explicit production-approval unknown and false-absence behavior.

### Product/release governance

- Added explicit supported-general, WFF-profile compatibility and internal/experimental surface classification.
- Added 1.x schema/API compatibility policy.
- Added explicit single-authority rollback policy with no peer dual-write.
- Generalized release-pack language for v1.0 while retaining the top-level `EKRI/` Git scanner-control installation model.

## Authority / Migration Result

v0.9 M0 semantic writer-path denominator:

```text
major semantic writer paths: 6
primary semantic output families: 7
```

v1.0 does not attempt to collapse all knowledge families into one writer/store. It preserves one authority per semantic slice.

The important convergence result is that Capability now has exactly one semantic authority and the pre-v1.0 duplicate Catalog builder/evaluator has been retired. Query and compatibility surfaces derive from that authority.

## Claim Ceiling

EKRI v1.0.0 supports a general evidence-bounded Engineering Knowledge Model / Query/View architecture with one-authority-per-slice semantics, one completed semantic-authority cutover/legacy-writer retirement chain, bounded Flow/Handoff querying, WFF + non-WFF conformance and preserved identity/ownership/lifecycle authority firewalls.

It does not claim universal ontology completeness, exhaustive dependency/absence proof, autonomous ownership/retirement/deletion governance, production approval, host application production readiness, or complete future Flow/Decision/Claim/Code Graph/distributed-trace/domain-profile coverage.
