# EKRI v1.1.0 — Adaptive Knowledge Acquisition

Status: published release record.

EKRI v1.1.0 adds mission-oriented adaptive knowledge acquisition over the stable v1.0 Engineering Knowledge System. It improves how an Agent reuses Project Knowledge, exposes stale/missing knowledge, budgets evidence acquisition and stops a bounded WAE loop when the mission is sufficiently informed.

## Added

- exact source-bound Mission Context with Project Knowledge v1/v2 freshness;
- Competency Questions and mechanical Knowledge Sufficiency assessment;
- disposable typed Mission Exploration Plans with explicit budgets and stop/return conditions;
- a generic exploration-operator vocabulary without technology-stack Profile directories;
- exact Git target-blob Evidence Receipts;
- bounded WAE acquisition traces with challenge/reconciliation and recomputed state/budget validation;
- non-authoritative Candidate Knowledge Deltas and family-authority routing;
- heterogeneous conformance over service, interaction-client and data-pipeline shapes;
- WFF v1.9.2 planned exploration-economy audit.

## Preserved from v1.0

Six major semantic writer paths / seven primary semantic families, one-authority-per-slice semantics, Capability cutover/legacy-writer retirement, evidence/unknown/conflicting boundaries, Project Knowledge Asset v1/v2 compatibility and No Active Self-Scan remain unchanged.

## Boundaries

v1.1 does not add a technology methodology/Profile matrix, Human Projection product, PX route authority, convergence discovery, always-on scanner, general Agent runtime, peer semantic store, direct Candidate Delta promotion, autonomous refactoring, UAT, production readiness or owner approval.

The economy audit reports planned exploration ceilings, not measured token/time/money savings.

The release-gate scope is anchored to the EKRI v1.1 program merge/candidate delta. Later WFF-only descendant commits do not become EKRI v1.1 product scope; EKRI follow-up commits remain auditable under the same gate. After publication, the gate accepts the release tag only when it resolves to the frozen validated v1.1 source.

The formal release tag is `ekri/v1.1.0`; the published `ekri/v1.0.0` tag/source remains immutable.
