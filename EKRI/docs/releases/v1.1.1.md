# EKRI v1.1.1 — Official Skills Entry Surface

Status: pre-publication hotfix candidate.

EKRI v1.1.1 fixes a release-level usability gap in v1.1.0: the product exposed its runtime, CLI and Python API but did not ship an official AI-facing Skill entry surface.

## Added

- `using-ekri` — top-level admission and routing Skill;
- `ekri-init` — first connection of an existing project to EKRI without forcing a whole-repository scan;
- `ekri-refresh` — incremental refresh when project knowledge is stale, missing or conflicting;
- `ekri-query` — L0-L3 progressive engineering-knowledge query Skill;
- `install_ekri_skills.py` — validates, lists and installs the complete official Skill directories into a caller-supplied Agent skills directory;
- machine-readable v1.1.1 Skill-surface classification and release-gate checks;
- release-pack requirements that fail closed if any official Skill or the installer is missing;
- an AI-Agent-only target-project access contract: Skills are read-only by default, and any EKRI knowledge persistence requires explicit user authorization and is limited to `.EKRI/project/**`, which should be tracked as a project asset when appropriate;
- a maintained EKRI product-version compatibility list based on Project Knowledge asset-layout generations. `1.1.0` and `1.1.1` remain fully compatible because the asset layout did not change; `1.0.0` and `1.1.x` belong to different layout generations.

## Preserved

v1.1.1 does not change the Engineering Knowledge Model, the six major semantic writer paths, the seven primary semantic families, the current Project Knowledge Asset v2 layout, Adaptive Knowledge Acquisition authority boundaries, No Active Self-Scan, or the published v1.1.0 source identity.

## Skill model

The official user-facing action set is intentionally small:

```text
using-ekri
  -> ekri-init
  -> ekri-refresh
  -> ekri-query
```

The Skills are designed for AI Agents and route them to existing EKRI capabilities. They do not mirror every internal module or knowledge family into a separate Skill, and they do not modify target-project source, configuration, tests or business files. The only allowed target-project write is an explicitly user-authorized EKRI knowledge asset under `.EKRI/project/**`; the Skill does not commit Git on the user's behalf.

## Claim ceiling

This hotfix proves a packaged and installable AI-facing Skill entry surface over existing EKRI capabilities. It does not prove universal Agent-platform compatibility, autonomous semantic acceptance, exhaustive project reconstruction, safe deletion, refactoring correctness, UAT or production readiness.
